# 复杂故事写作指南

> 当故事涉及多角色、多时间线、跨时代、平行叙事等复杂结构时，用 ReadFile 加载本文件。简单线性故事不需要。

## 何时算"复杂故事"

满足以下任一条件：
- 角色超过 8 个
- 时间跨度超过单一场景序列（有闪回、跨年代）
- 有 2 条以上并行故事线
- 需要 5 幕以上
- 角色之间有多代际/多阵营的复杂关系网

## Parts：超长故事分部

当故事超过 5 幕时，用 `parts` 把幕组织成"部"：

```json
{
  "parts": [
    {
      "id": "part_1",
      "title": "第一部：建村",
      "summary": "何塞带领族人穿越丛林，建立马孔多。",
      "acts": [
        {"id": "act_1", "title": "...", "scenes": [...]},
        {"id": "act_2", "title": "...", "scenes": [...]}
      ]
    },
    {
      "id": "part_2",
      "title": "第二部：繁荣",
      "summary": "马孔多从小村庄发展为城镇。",
      "acts": [...]
    }
  ]
}
```

每个 part 是一个独立的叙事阶段。Part ID 格式：`part_{N}`。

## Tags：多维角色分组

复杂故事的角色需要多维分类。用 `tags` 数组替代单一 `group`：

```json
{
  "id": "char_aureliano_ii",
  "name": "奥雷里亚诺第二",
  "tags": ["布恩迪亚家族", "第三代", "主角", "马孔多"],
  "fixed_traits": {...}
}
```

常用维度：
- **角色类型**：主角、配角、反派、群众
- **阵营/家族**：布恩迪亚家族、政府军、工会
- **世代**：第一代、第二代、第三代
- **地域**：马孔多、首都、海外

前端可按任意维度筛选和分组。

## Thread：多线叙事

当故事有并行的故事线时，给场景添加 `thread`：

```json
{
  "id": "scene_015",
  "title": "何塞的炼金实验",
  "thread": "何塞线",
  ...
},
{
  "id": "scene_016",
  "title": "乌苏拉的家务",
  "thread": "乌苏拉线",
  ...
}
```

同一 `thread` 的场景构成一条连贯的叙事线。不同 thread 的场景可以交错排列在同一幕中。导演和剪辑会根据 thread 决定交叉剪辑方式。

**注意**：简单故事不填 `thread`，所有场景隐含为同一条故事线。

## Narrative Mode：非线性叙事

当场景不是按时间顺序排列时，用 `narrative_mode` 标注：

| 模式 | 说明 | 示例 |
|------|------|------|
| `present` | 默认，当前时间线 | 不需要填写 |
| `flashback` | 闪回，比当前时间线更早 | 角色回忆童年 |
| `flash_forward` | 闪前，比当前时间线更晚 | 预示未来事件 |
| `parallel` | 同一时间，不同地点 | 两个角色在不同地点的同时行动 |

```json
{
  "id": "scene_020",
  "title": "童年的河边",
  "narrative_mode": "flashback",
  "period": "三十年前",
  ...
}
```

`narrative_mode` 通常配合 `period` 使用，让时间关系明确。

## Period：跨时代叙事

当故事跨越较长时间时，用 `period` 标记每个场景的时代：

```json
{"id": "scene_001", "period": "1850年代", ...},
{"id": "scene_010", "period": "1880年代", ...},
{"id": "scene_025", "period": "1920年代", ...}
```

`period` 是自由文本，常用格式：
- 绝对年代：`"1920年代初"`、`"2035年"`
- 相对时间：`"二十年后"`、`"三代之后"`
- 世代标记：`"第二代"`

## 关系演变

复杂故事中角色关系会多次变化。用 `from`/`until` 追踪：

```json
"relationships": {
  "char_jose": [
    {"kind": "挚友", "until": "scene_015"},
    {"kind": "政治对手", "from": "scene_016", "until": "scene_030"},
    {"kind": "和解", "from": "scene_031"}
  ]
}
```

每段关系有明确的时间范围，不重叠。前端可以据此展示关系时间线。

## AI 生成约束下的写作注意事项

复杂故事面临更大的 AI 生成一致性挑战：

### 1. 控制同时在场的角色数

每个场景建议不超过 4 个角色同时出现。AI 视频生成在多角色场景中容易出现：
- 角色混淆（A 和 B 的外形互换）
- 角色消失或多出
- 空间关系混乱

如需大场面（如集会、战斗），用叙事技巧拆分：先全景介绍环境，然后分镜聚焦少数角色。

### 2. 角色跨时代的外观管理

同一角色在不同时代的外观差异必须在 `character_states.appearance` 中显式描述：

```json
// 第一代：年轻时
"character_states": {
  "char_jose": {
    "emotion": "充满激情",
    "appearance": "二十岁出头，黑发浓密，身穿白色麻布衬衫"
  }
}

// 第三代：老年
"character_states": {
  "char_jose": {
    "emotion": "疲惫执着",
    "appearance": "头发全白，面容枯瘦，身穿破旧的实验服"
  }
}
```

不写 `appearance` 就默认用 `fixed_traits`——如果角色老了 50 年但没写外观变化，视频里他还是年轻的样子。

### 3. 地点的时代变化

同一地点在不同时代可能面目全非。用 `location_state` 描述每个时代的地点状态：

```json
// 1850年代：初建
"location_state": {
  "appearance": "泥土路，几间茅草屋，周围是原始丛林",
  "lighting": "热带阳光直射"
}

// 1920年代：繁荣
"location_state": {
  "appearance": "石板街道，两层楼房，电线杆，火车站",
  "lighting": "城镇灯光初上"
}
```

### 4. 名字相似的角色

某些故事（如百年孤独）有多个同名或近名角色。必须在 `fixed_traits` 中给出足够区分度的视觉特征：

- 不要：两个都叫"奥雷里亚诺"且外形描述模糊
- 要：第一个有"额头上的十字伤疤"，第二个有"永远戴着的金丝眼镜"

`tags` 中标注世代也有助于区分：`["第一代"]` vs `["第三代"]`。

### 5. 视觉可表达性

复杂故事更容易出现抽象内容。始终检查：这个场景能被"拍"出来吗？

- 避免："马孔多的命运之轮开始转动" — 无法拍摄
- 改为："乌苏拉站在空荡荡的老宅门口，看着远处的火车冒着黑烟驶来" — 可以拍摄
